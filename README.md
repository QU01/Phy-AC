> **Spec → verified geometry → printable parts.** The engineer writes
> six numbers (target PR, mass flow, max RPM, max tip speed, max tip
> radius, inlet conditions) and receives, on a laptop CPU and without
> proposing any geometry whatsoever: the physically verified feasible
> Pareto front, the recommended multistage design, the per-stage loss and
> loading breakdown, the CFD boundary conditions, the bill of materials,
> **and the 3D-printable STLs of every part — shaft, per-stage bladed
> discs, and per-stage casing rings with bolted flanges and bleed port.**
>
> Documents: [docs/Quasar_PhyAC_Science.md](docs/Quasar_PhyAC_Science.md)
> (equations, pseudocode, references) ·
> [docs/VALIDATION.md](docs/VALIDATION.md) (physical validation vs NASA
> machines). Phy-AC is the axial sibling of **Phy-CC** (centrifugal
> compressors) and shares its architecture: *calibrated physics prior →
> residual deep ensemble with uncertainty gate → constrained NSGA-II →
> self-contained report*.

## Pipeline

```
spec (6 numbers)
   │   phyac_cli.py · neural_optimizer.design()          [Python, layers 1–4]
   ▼
optimal verified design (θ vector + physical record)
   │   geometry_generator.py                             [layer 5a]
   ▼
geometry/axial_compressor.json · bom.csv · CFX BCs ────→ report.html [layer 5b]
   │   PhyACImport.FromContractJson(...) + PicoGK        [layer 5c, C#/.NET 9]
   ▼
Shaft + RotorStage{i} + StatorRing{i} STLs  (every part, printable)
```

Layers 1–5b are Python (core: NumPy only). Layer 5c is the C# library
**AxialCompressorDesigner** (.NET 9 + [PicoGK](https://picogk.org) 2.2.0
NuGet package), which converts the optimized design into the real machine
parts — turbojet construction, split where real bolted joints sit:

| Part | Exported File | Content |
|---|---|---|
| **Drive shaft** | `<Name>_Shaft.stl` | Shaft with mounting stubs past both ends and center bore |
| **Bladed disc** ×N | `<Name>_RotorStage{i}.stl` | Disc web + hub flow-path shell segment (incl. spacer under its stator) + rotor blades of stage i |
| **Casing ring** ×N | `<Name>_StatorRing{i}.stl` | Casing shell segment + stator vanes; first/last rings carry the bolted flanges; the bleed-stage ring carries the bleed port |
| **Rotor / Casing** (views) | `<Name>_Rotor.stl` / `<Name>_Casing.stl` | Unions in running position |
| **Assembly** (view) | `<Name>.stl` | Everything (for inspection only) |

Split planes sit mid-gap between one stage's stator trailing edge and the
next stage's rotor leading edge; each disc bore slides over the shaft.

## Quickstart

The CLI features a colorized interface with ASCII art, panels, and live
progress. The easiest way to start is the **interactive wizard**, which
asks for the specification numbers (press Enter to accept defaults):

```bash
python phyac_cli.py --interactive        # or -i
```

```bash
# 1. Aerodynamic design — quick smoke run (~2 min, L0 fidelity):
python phyac_cli.py --pr 4.0 --mdot 25 --quick --fidelity L0 --outdir runs/smoke

#    Full run (with turbo-design installed, L1 verifies the winners):
python phyac_cli.py --pr 4.0 --mdot 25 --rpm-max 18000 --utip-max 460 \
    --rtip-max 400 --rounds 5 --n-init 320 --outdir runs/pr4

#    With CFD calibration pairs (closes the loop Noyron-style):
python phyac_cli.py --pr 4.0 --mdot 25 --hifi-pairs cfx_pairs.json --outdir runs/cal
```

### Engineer-in-the-loop controls

```bash
# Pin design variables and optimize the rest (repeatable), custom seed:
python phyac_cli.py --pr 4 --mdot 25 --fix n_stages=5 --fix phi1=0.60 --seed 42

# Evaluate ONE given design (no optimization) with full deliverables
# (the 10 design vars — n_stages,RPM,HTR,phi1,psi_mid,psi_slope,Rx,
#  sigma_r,sigma_s,AR — the operating point comes from the spec flags):
python phyac_cli.py --eval-theta "4,12500,0.62,0.55,0.32,-0.10,0.60,1.20,1.10,2.20" \
    --pr 4 --mdot 25 --outdir runs/eval --map

# Warm-start a run from its checkpoint (dataset replaces the LHS):
python phyac_cli.py --outdir runs/pr4 --resume --rounds 3

# Inspect the verified Pareto front of a finished run, then regenerate
# the full deliverables (report/geometry/STL) for any point of it:
python phyac_cli.py --outdir runs/pr4 --list-pareto
python phyac_cli.py --outdir runs/pr4 --pareto-pick 3 --stl
```

Interface control: `--no-color` (plain text, also respects `NO_COLOR`),
`--quiet`/`-q` (milestones only). The styling lives in
[`cli_style.py`](cli_style.py) (no external dependencies). Full examples:
`python phyac_cli.py --help`.

### 2. 3D-Printable STLs from the Optimized Design (Layer 5c)

#### Option A: Direct automated generation (recommended)

```bash
# Generate all parts with default 0.5mm voxel resolution:
python phyac_cli.py --pr 4.0 --mdot 25 --quick --stl

# Custom voxel resolution (0.3–0.4 mm for final parts):
python phyac_cli.py --pr 4.0 --mdot 25 --quick --voxel 0.4
```

#### Option B: Manual invocation

```powershell
& "C:\Program Files\dotnet\dotnet.exe" build AxialCompressorDesigner.sln
& "C:\Program Files\dotnet\dotnet.exe" `
  "AxialCompressorDesigner.Example\bin\Debug\net9.0-windows\AxialCompressorDesigner.Example.dll" `
  runs\pr4\geometry\axial_compressor.json output\pr4 0.4   # json, outDir, voxel mm
```

Python phase outputs in `<outdir>/`: `report.html` (self-contained; Pareto
front, per-stage table, Smith chart, loss breakdown, velocity triangles,
annulus, structural margins, CFD BCs, traceability — plus the matplotlib
section when installed; skip with `--no-figures`), `figures/`, `geometry/`
(`axial_compressor.json` — the schema `phyac-axial-1` contract consumed by
layer 5c, with per-row camber sections, annulus polylines, assembly
parameters and the structural block —, `annulus.csv`, `stage_summary.csv`,
`bom.csv`, `blade_stage0.step` if CadQuery is available), `dataset.csv`
(data flywheel), `phyac_run.json` (traceable checkpoint), `phys_cache.jsonl`
(persistent cache of expensive L1 evaluations), `map.csv` with `--map`.

C# phase outputs: one STL per part plus the union views (binary, in mm).

## Python API (layers 1–5b)

```python
from neural_optimizer import DesignSpec, design
spec = DesignSpec(PR_target=4.0, massflow=25.0, RPM_max=18_000,
                  U_tip_max=460.0, r_tip_max_mm=400.0,
                  n_stages_max=8, material="Ti-6Al-4V")
out = design(spec)              # → {theta, record, pareto_front, history}
```

## C# API (layer 5c)

The public surface consists of **three types**: the parameters class, the
static entry point, and the Phy-AC importer.

```csharp
using AxialCompressorDesigner;

// From a Phy-AC run (product path):
var p = PhyACImport.FromContractJson(@"runs\pr4\geometry\axial_compressor.json");
string stlPath = AxialCompressorBuilder.Build(
    p, outputDir: @"C:\output\path", showViewer: false);
// stlPath = assembly; _Shaft, _RotorStage{i}, _StatorRing{i}, _Rotor and
// _Casing STLs are created alongside
```

The C# layer is deliberately **data-driven**: all blade math (profiles,
metal angles, free vortex) lives in Python; the contract carries fully
resolved camber sections per span station and the C# only transforms,
stitches and voxelizes (see `.agent/axial-compressor-pattern.md`).

### axial_compressor.json → Parameters Mapping

| Contract block | C# Parameter(s) | Rule |
|---|---|---|
| `annulus.hub` / `annulus.tip` | `HubLine` / `TipLine` | direct polylines [z, r] mm |
| `annulus.tip_clearance_mm` | `TipClearanceMm` | running gap at the blade free end |
| `stages[i].rotor/stator` | one `RowParams` each | blade count, z slot, span sections |
| `sections[j].camber_points` | `SectionParams.CamberPoints` | camber mid-surface, chord frame, centroid at origin; thickened by `voxMeshShell` (½·`thickness_mm`) |
| `sections[j].stagger_deg` | `SectionParams.StaggerDeg` | **signed** (rotor +, stator −); the builder applies the signed rotation uniformly |
| `structural.drum_inner_r_mm` | `DrumInnerRadiusMm` | shaft radius under the discs |
| `assembly.*` | shaft/disc/flange/bleed params | turbojet construction detail (see below) |

### Parameters

All distances in millimeters. Contract `assembly` block defaults in
parentheses.

| Parameter | Default | Meaning |
|---|---|---|
| `VoxelSizeMm` | 0.5 | Voxel field resolution (0.8 draft, 0.3–0.4 final) |
| `TipClearanceMm` | contract | Rotor tip / stator hub running clearance |
| `RootSinkMm` | 1.5 | Blade root sink into its body (weld) |
| `ShaftStubMm` | 30 | Shaft stub past each end (mounting land) |
| `ShaftBoreFrac` | 0.35 | Center bore / shaft radius |
| `HubWallMm` | 5 | Hub flow-path shell wall (drum, not billet) |
| `DiskWebFrac` | 0.5 | Disc web thickness / row axial chord (clamped 4–14) |
| `FlangeBoltCount` / `FlangeBoltDMm` | 12 / 6 | Bolt circle of both end flanges |
| `FlangeWMm` / `FlangeTMm` | 12 / 8 | Flange radial width / axial thickness |
| `BleedStage` | mid stage | 1-based stage whose casing ring carries the bleed port |
| `BleedHoleDMm` / `BleedBossDMm` / `BleedBossHMm` | 18 / 32 / 14 | Bleed port hole, boss diameter and boss height |

## Geometry (layer 5c)

Convention: **Z is the rotational axis**; gas flows in +Z. Blade rows are
built with the Phy-CC v3 vane recipe: the camber **mid-surface** (one sheet
of quads per blade, densified to ~25 span ribs) is thickened with
`Voxels.voxMeshShell`, which offsets in the signed-distance domain and
cannot self-intersect — LE/TE and tip come out rounded at ½·thickness.
Blade roots sink into their body; free ends are pulled in by clearance +
shell radius so the inflation does not eat the running gap. Axial row
slots are computed from the **exact** rotated-camber envelope of every
section (the hub runs at much lower stagger than the tip), so parts never
overlap — a regression test guards this.

## Compile and Run Layer 5c

```powershell
& "C:\Program Files\dotnet\dotnet.exe" build AxialCompressorDesigner.sln

& "C:\Program Files\dotnet\dotnet.exe" `
  "AxialCompressorDesigner.Example\bin\Debug\net9.0-windows\AxialCompressorDesigner.Example.dll" `
  <path\to\axial_compressor.json> [outDir] [voxelMm]
```

A 5-stage machine (Ø500 mm) takes ~20–25 min at 0.8 mm voxel (all parts);
finer voxels scale roughly with 1/voxel³. Rotor and casing parts are
independent voxel fields built in the same `Library.Go` session.

### Runtime Requirements (Windows)

- **.NET 9 SDK + x64 runtime** in `C:\Program Files\dotnet\`.
- PicoGK native libraries ship inside the NuGet package and resolve
  automatically on x64 hosts.

| Symptom | Cause |
|---|---|
| `DllNotFoundException: picogk.*` | Native DLLs not located / not an x64 host |
| `part '...' is empty` | Degenerated parameters (radii/thickness vs voxel size) |
| camber point count differs | Layer 5a contract corrupted — sections must share point counts |

## Verification and Validation

```bash
python test_phyac.py               # verification: 54 checks
python validation/validate.py      # validation: NASA machines → RESULTS.md
python data_pipeline.py            # data anchors: rebuild + SHA-256 verify
```

**Verification** (`test_phyac.py` — do we solve the equations right?)
covers triangle identities, Euler/enthalpy conservation, the isentropic
limit, constraint-vector continuity through choke, profile/contract
invariants (equal point counts, signed staggers, no axial overlap), the
disc solver vs the exact Timoshenko solution, Deb dominance rules and the
ensemble gate, and bit-to-bit reproducibility (seed 71).

**Validation** (`validation/` — do we solve the right equations?) grades
the meanline against measured NASA machines with **no per-machine
recalibration** — the θ of each machine reproduces its published annulus
and measured work; the model is graded on its loss prediction → (η, PR).
Current table in [validation/RESULTS.md](validation/RESULTS.md):

| Machine | ΔPR | Δη |
|---|---|---|
| NASA Stage 35 (transonic stage) | +0.9% | +1.3 pts |
| NASA Rotor 37 (transonic rotor) | −1.8% | −2.3 pts |
| NASA Rotor 67 (transonic fan) | −1.2% | −2.5 pts |
| GE/NASA E³ HPC (10 stages) | −4.4% | −1.3 pts |

Adding a machine is a data entry in
[validation/machines.py](validation/machines.py); internal regression
anchors freeze the physics against silent drift (`--freeze-anchors`).

## Current Status and Declared Limits (v0.1)

- **Repeating-stage parameterization** (ψ_mid + ψ_slope, single Rx/φ):
  real multistage machines vary φ/Rx per stage — the E³ validation
  tolerance is relaxed for this, and it is the first candidate for a
  richer θ in a later phase.
- **L0 shock model** is a two-point normal-shock average with
  K_SHOCK = 0.70 calibrated on Rotor 37/67; beyond M_tip ≈ 1.5 it is
  extrapolation.
- **L1 (turbo-design 1.4.2)** requires the patches documented in
  `physics_core.py` §3 and runs in meanline mode (1 streamline) inside a
  timeout-guarded subprocess; each stage is transformed work-preservingly
  (TD3's pressure-balance marching does not propagate inter-row swirl
  into the Euler work). Measured: 95% solve success on feasible samples,
  PR correlation r ≈ 0.95 vs L0, systematic PR ratio ≈ 0.94 absorbed by
  `HiFiCalibration`.
- **Blading** uses circular-arc camber with NACA 65-010 / biconvex
  thickness and uniform-thickness printed vanes (camber sheet +
  `voxMeshShell`); for CFD-faithful blades, use TD3's BladeGen/AGF path.
- Materials are handbook-typical; substitute certified specs for real
  design. The assembly view STL is for inspection only — print the parts.
